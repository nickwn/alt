Adaptive Exact Predicates in Distance Space

The two predicates from my Delaunay triangulation post, orient and in_circle, only ever return a sign. Both are polynomials in the entries of a squared distance matrix, and for nearly degenerate input (almost collinear or almost cocircular points) the rounding error in evaluating them can be larger than the value itself, so the sign you get back is garbage. In a topological algorithm like stitch_from that means an inconsistent mesh, or a loop that never terminates.

The standard fix is Shewchuk's adaptive precision arithmetic: evaluate in plain floating point, bound the error, and only if the bound doesn't certify the sign, redo the computation with more precision. His predicates take point coordinates, however, whereas ours take squared distances, so they don't apply directly. In this post I rederive the two predicates in a form that is cheap to evaluate exactly, then build adaptive versions of them. Throughout, the squared distances are treated as the exact input, so it's the predicates themselves that are made exact, not the process that produced the distances.

Rewriting the predicates

I'll use the labeling from the code in the previous post: the points i, j, k, and l give the squared distances a = |ki|², b = |jk|², c = |ij|², d = |il|², e = |jl|², and f = |kl|². That is, in this post a, b, ... are the squared quantities themselves, as in the code (a2, b2, ...).

For orient I'll use the form from the dot product derivation, where with P=a+d-f, Q=a+c-b, and R=d+c-e, the point l is across edge ij from k exactly when

2cP-QR<0.

(P, Q, and R are twice the dot products ik→·il→, ik→·ij→, and il→·ij→, so the left hand side is four times the dot product of the two triangles' normals. This is written directly in the labeling of the code, which is why a and b aren't swapped like in the bary_denorm version.) This is a good form for exact arithmetic: three sums of three terms each, followed by two products and a difference.

For in_circle I'll use the square root free form from the previous post. With x=d+e-c and y=a+b-c, l (which must be across ij from k) is outside the circumcircle of kij if x≥0 and y≥0, inside it if x≤0 and y≤0 (and they aren't both zero), and otherwise, when the signs differ, it is inside if L>0 and x<0, or if L<0 and y<0, where

L=abx2-dey2.

Here the squares of x and y are the only place where the degree gets high, and since x and y are exactly computable sums, we can tell the sign cases apart exactly without ever computing L.

Error-free transformations

The key tool is that the rounding error of floating point addition and multiplication is itself a floating point number, and can be computed exactly. For doubles a and b, Knuth's two_sum computes x=fl(a+b) and an y such that x+y=a+b exactly, using six floating point operations and no branches. The product has an equivalent, two_product, which with a fused multiply-add is just x=fl(ab) and y=fma(a,b,-x).

With these, a real number can be stored as an expansion: the exact sum of a list of non-overlapping doubles, sorted by magnitude. Because the components don't overlap, the largest one dominates all the others combined, so the sign of an expansion is the sign of its last component. Adding a double to an expansion is a chain of two_sums (Shewchuk's grow_expansion), multiplying an expansion by a double is a chain of two_products and two_sums (scale_expansion), and the rest follow by repeating those: adding two expansions grows one by each component of the other, and multiplying two expansions scales one by each component of the other and adds up the results. None of these round, so exact answers are just a matter of using enough components. The cost is that the number of components can multiply, which is what makes the exact path slow and why we only want to take it when we have to.

Orient in three stages

Stage A is to just evaluate the formula in floating point,

D^=fl(2cP^-Q^R^),

where each hat is a sum of three terms computed left to right. Let ε=2-53 be the unit roundoff. Every input is a squared distance and so non-negative, which makes error analysis pleasant because there is never any cancellation in the absolute values of the terms. For P, a standard calculation gives

|P^-P|≤2ε(1+ε)SP,SP=a+d+f

and similarly for Q and R with SQ=a+c+b and SR=d+c+e. Propagating these through the product (a rounding of relative size ε per operation) and the final subtraction, and keeping the first order terms, the error of the first product is at most about 3ε·2cSP, that of the second at most about 5εSQSR, and the subtraction adds one more ε times the sum of the two. Collecting terms and rounding up for the second order terms gives

|D^-D|≤8ε·perm,perm=2cSP+SQSR.

(This is called the "permanent" in Shewchuk's work: the formula evaluated with all signs made positive.) If |D^| is bigger than this bound, then D^ has the right sign and we're done. For well separated points this is nearly always the case.

Stage B uses the fact that two_sum also gives us the error of each sum. Writing P=P^+pt and likewise for Q and R, we have

D=(2cP^-Q^R^)+(2cpt-Q^rt-R^qt)-qtrt.

The first term (the "head") is computed exactly with two two_products and an expansion sum. The second (the "tail") is smaller than the first by a factor of about ε, so it's fine to compute it in floating point. The last term is smaller by another factor of ε and is dropped entirely. Since |pt|≤2εSP (and so on), the dropped term is at most 4ε2SQSR, and accounting for the rounding errors in the tail we end up with

|D^-D|≤3ε|D^|+16ε2·perm,

which is a factor of ε smaller than the Stage A bound in the case that matters, when D is small relative to perm. The extra term is there to deal with the rounding when estimating the sum of the head's components.

Stage C computes everything exactly: P, Q, and R as expansions, then 2cP by scaling and QR by expansion multiplication, and finally the sign of the difference. Nothing is estimated, so there are no bounds to worry about.

In_circle in the same way

The only work that needs to be exact up front is the signs of x and y. They're sums of three non-negative terms, and so the same stage A analysis gives |x^-x|≤3ε(d+e+c): if x^ is outside this interval its sign is correct, and if not we fall back to an exact expansion sum of three terms, which is cheap. For random points about two thirds of the calls (65% in my test) end here, since the signs of x and y already settle it.

If the signs differ, we need the sign of L. Here the same three stages apply, now with

perm=abX2+deY2,X=d+e+c,Y=a+b+c.

In stage A, x^ and y^ have errors of about 2εX and 2εY, squaring doubles the relative error and adds a rounding, and then the two products and the subtraction add three more roundings in total, which comes to about 8ε·perm after the second order terms are absorbed. I use 9ε·perm. In stage B, we write x=x^+xt and y=y^+yt, so

L=(abx^2-dey^2)+2(abx^xt-dey^yt)+(abxt2-deyt2).

We compute the first group exactly, the second in floating point, and drop the third, which is at most about 4ε2·perm. Adding the roundings of the tail gives the bound 3ε|L^|+32ε2·perm. Stage C is the exact evaluation of L with expansions. Because x and y are expansions of up to three components and L multiplies four numbers of that kind, the exact expansion can get to a hundred or so components in the worst case, and since I don't want to allocate for this, Expansion in the code below is a fixed-capacity array.

One caveat I should be honest about: the constants above come from a first-order accounting of the roundings in which I rounded up generously to absorb the ε2 terms, not from a careful proof in the style of Shewchuk's paper. Everything is conservative rather than tight, but if you need a guarantee for your own application, then take the bounds as a derivation sketch and check them.

Code

Here's the whole thing as a single C++ header. It needs round-to-nearest doubles with no extended precision, so no x87 and compile with -ffp-contract=off so the compiler doesn't fuse operations that the error analysis relies on being separate. std::fma must also be correctly rounded, which it is if the hardware has one or if the standard library emulates it properly. 

#pragma once
#include <cmath>

// Adaptive exact predicates on squared distances.
// Requires round-to-nearest-even doubles with no extended precision,
// and no floating point contraction (-ffp-contract=off).
// Inputs must be finite and non-negative, and products shouldn't over/underflow.
namespace exact_d2 {

constexpr double eps = 0x1p-53; // unit roundoff

// ---- Error-free transformations ------------------------------------

// x + y == a + b exactly, with x = fl(a + b)
inline void two_sum(double a, double b, double& x, double& y)
{
    x = a + b;
    const double bv = x - a;
    const double av = x - bv;
    y = (a - av) + (b - bv);
}

// Same as two_sum, but requires |a| >= |b| (or a == 0)
inline void fast_two_sum(double a, double b, double& x, double& y)
{
    x = a + b;
    y = b - (x - a);
}

// x + y == a * b exactly, with x = fl(a * b)
inline void two_product(double a, double b, double& x, double& y)
{
    x = a * b;
    y = std::fma(a, b, -x);
}

// ---- Expansions -----------------------------------------------------

// A real number stored as the exact sum of non-overlapping doubles,
// ordered from smallest to largest magnitude.
struct Expansion
{
    static constexpr int cap = 160;
    double c[cap];
    int n = 0;
};

inline Expansion expansion_of(double lo, double hi)
{
    Expansion e;
    e.c[0] = lo;
    e.c[1] = hi;
    e.n = 2;
    return e;
}

inline Expansion expansion_of(double a)
{
    Expansion e;
    e.c[0] = a;
    e.n = 1;
    return e;
}

inline Expansion negate(Expansion e)
{
    for (int i = 0; i < e.n; i++) e.c[i] = -e.c[i];
    return e;
}

// e + b
inline Expansion grow(const Expansion& e, double b)
{
    Expansion h;
    double q = b;
    for (int i = 0; i < e.n; i++)
    {
        double q_new, hh;
        two_sum(q, e.c[i], q_new, hh);
        q = q_new;
        if (hh != 0.) h.c[h.n++] = hh;
    }
    if (q != 0. || h.n == 0) h.c[h.n++] = q;
    return h;
}

// e + f
inline Expansion sum(Expansion e, const Expansion& f)
{
    for (int i = 0; i < f.n; i++) e = grow(e, f.c[i]);
    return e;
}

// e * b
inline Expansion scale(const Expansion& e, double b)
{
    Expansion h;
    double q, hh;
    two_product(e.c[0], b, q, hh);
    if (hh != 0.) h.c[h.n++] = hh;
    for (int i = 1; i < e.n; i++)
    {
        double p1, p0, s;
        two_product(e.c[i], b, p1, p0);
        two_sum(q, p0, s, hh);
        if (hh != 0.) h.c[h.n++] = hh;
        fast_two_sum(p1, s, q, hh);
        if (hh != 0.) h.c[h.n++] = hh;
    }
    if (q != 0. || h.n == 0) h.c[h.n++] = q;
    return h;
}

// e * f
inline Expansion product(const Expansion& e, const Expansion& f)
{
    Expansion h = scale(e, f.c[0]);
    for (int i = 1; i < f.n; i++) h = sum(h, scale(e, f.c[i]));
    return h;
}

// a * b exactly
inline Expansion product_of(double a, double b)
{
    double x, y;
    two_product(a, b, x, y);
    return expansion_of(y, x);
}

// The largest component dominates, so it has the sign of the whole sum.
inline int sign(const Expansion& e)
{
    const double top = e.c[e.n - 1];
    return (top > 0.) - (top < 0.);
}

// Approximation of the sum, with relative error O(eps)
inline double estimate(const Expansion& e)
{
    double s = 0.;
    for (int i = 0; i < e.n; i++) s += e.c[i];
    return s;
}

// ---- Shared helpers ---------------------------------------------------

// Returns h = fl(fl(a + b) - c) and sets tail such that 
// a + b - c == h + tail up to a rounding error in tail.
inline double sum3(double a, double b, double c, double& tail)
{
    double s, e1, h, e2;
    two_sum(a, b, s, e1);
    two_sum(s, -c, h, e2);
    tail = e1 + e2;
    return h;
}

inline Expansion sum3_exact(double a, double b, double c)
{
    return grow(grow(expansion_of(a), b), -c);
}

// Exact sign of a + b - c for a, b, c >= 0
inline int sign_sum3(double a, double b, double c)
{
    const double h = (a + b) - c;
    if (std::fabs(h) > 3. * eps * (a + b + c)) return (h > 0.) - (h < 0.);
    return sign(sum3_exact(a, b, c));
}

// A stage result: an estimate of the value and a bound on its error.
struct Stage { double det, err; };

// =======================================================================
// orient
//   2 c2 (a2 + d2 - f2) - (a2 + c2 - b2) (d2 + c2 - e2)
// is negative when l is across edge ij from k.
// =======================================================================

inline double orient_perm(double a2, double b2, double c2, double d2, double e2, double f2)
{
    return 2. * c2 * (a2 + d2 + f2) + (a2 + c2 + b2) * (d2 + c2 + e2);
}

inline Stage orient_a(double a2, double b2, double c2, double d2, double e2, double f2)
{
    const double P = (a2 + d2) - f2;
    const double Q = (a2 + c2) - b2;
    const double R = (d2 + c2) - e2;
    const double det = (2. * c2) * P - Q * R;
    return { det, 8. * eps * orient_perm(a2, b2, c2, d2, e2, f2) };
}

inline Stage orient_b(double a2, double b2, double c2, double d2, double e2, double f2)
{
    double tp, tq, tr;
    const double P = sum3(a2, d2, f2, tp);
    const double Q = sum3(a2, c2, b2, tq);
    const double R = sum3(d2, c2, e2, tr);

    // The head is computed exactly, the tails are only estimated.
    const Expansion head = sum(
        product_of(2. * c2, P), 
        negate(product_of(Q, R)));
    const double tail = (2. * c2) * tp - (Q * tr + R * tq);

    const double det = estimate(head) + tail;
    const double perm = orient_perm(a2, b2, c2, d2, e2, f2);
    return { det, 3. * eps * std::fabs(det) + 16. * eps * eps * perm };
}

inline double orient_exact(double a2, double b2, double c2, double d2, double e2, double f2)
{
    const Expansion P = sum3_exact(a2, d2, f2);
    const Expansion Q = sum3_exact(a2, c2, b2);
    const Expansion R = sum3_exact(d2, c2, e2);
    const Expansion det = sum(scale(P, 2. * c2), negate(product(Q, R)));
    return det.c[det.n - 1];
}

// Returns a value with the same sign as the exact result.
// stage (optional) is set to 0, 1, or 2 depending on how much work was needed.
inline double orient(
    double a2, double b2, double c2, double d2, double e2, double f2, 
    int* stage = nullptr)
{
    Stage s = orient_a(a2, b2, c2, d2, e2, f2);
    if (std::fabs(s.det) > s.err) { if (stage) *stage = 0; return s.det; }

    s = orient_b(a2, b2, c2, d2, e2, f2);
    if (std::fabs(s.det) > s.err) { if (stage) *stage = 1; return s.det; }

    if (stage) *stage = 2;
    return orient_exact(a2, b2, c2, d2, e2, f2);
}

// =======================================================================
// in_circle
// Let x = d2 + e2 - c2 and y = a2 + b2 - c2. l is inside the circumcircle 
// of kij (and across ij from k) iff a b x + d e y < 0, which is decided by
//   x >= 0 and y >= 0         -> false
//   x <= 0 and y <= 0         -> true
//   otherwise (x < 0 < y)     -> L > 0
//   otherwise (y < 0 < x)     -> L < 0
// where L = a2 b2 x^2 - d2 e2 y^2
// =======================================================================

inline double in_circle_perm(double a2, double b2, double c2, double d2, double e2)
{
    const double X = d2 + e2 + c2;
    const double Y = a2 + b2 + c2;
    return a2 * b2 * (X * X) + d2 * e2 * (Y * Y);
}

inline Stage in_circle_a(double a2, double b2, double c2, double d2, double e2)
{
    const double x = (d2 + e2) - c2;
    const double y = (a2 + b2) - c2;
    const double det = (a2 * b2) * (x * x) - (d2 * e2) * (y * y);
    return { det, 9. * eps * in_circle_perm(a2, b2, c2, d2, e2) };
}

inline Stage in_circle_b(double a2, double b2, double c2, double d2, double e2)
{
    double tx, ty;
    const double x = sum3(d2, e2, c2, tx);
    const double y = sum3(a2, b2, c2, ty);

    const Expansion head = sum(
        product(product_of(a2, b2), product_of(x, x)),
        negate(product(product_of(d2, e2), product_of(y, y))));
    // First order change due to the tails of x and y
    const double tail = 2. * ((a2 * b2) * x * tx - (d2 * e2) * y * ty);

    const double det = estimate(head) + tail;
    const double perm = in_circle_perm(a2, b2, c2, d2, e2);
    return { det, 3. * eps * std::fabs(det) + 32. * eps * eps * perm };
}

inline int in_circle_exact(double a2, double b2, double c2, double d2, double e2)
{
    const Expansion x = sum3_exact(d2, e2, c2);
    const Expansion y = sum3_exact(a2, b2, c2);
    const Expansion det = sum(
        product(product_of(a2, b2), product(x, x)),
        negate(product(product_of(d2, e2), product(y, y))));
    return sign(det);
}

// Returns whether l is inside the circumcircle of kij, exactly.
// stage (optional) is set to -1 if only the signs of x and y were needed, 
// otherwise 0, 1, or 2 depending on how much work was needed.
inline bool in_circle(
    double a2, double b2, double c2, double d2, double e2, 
    int* stage = nullptr)
{
    const int sx = sign_sum3(d2, e2, c2);
    const int sy = sign_sum3(a2, b2, c2);

    if (sx >= 0 && sy >= 0) { if (stage) *stage = -1; return false; }
    if (sx <= 0 && sy <= 0) { if (stage) *stage = -1; return true; }

    int s;
    Stage st = in_circle_a(a2, b2, c2, d2, e2);
    if (std::fabs(st.det) > st.err) 
    {
        if (stage) *stage = 0;
        s = (st.det > 0.) - (st.det < 0.);
    }
    else 
    {
        st = in_circle_b(a2, b2, c2, d2, e2);
        if (std::fabs(st.det) > st.err)
        {
            if (stage) *stage = 1;
            s = (st.det > 0.) - (st.det < 0.);
        }
        else
        {
            if (stage) *stage = 2;
            s = in_circle_exact(a2, b2, c2, d2, e2);
        }
    }
    return (sx < 0) ? s > 0 : s < 0;
}

} // namespace exact_d2

To use these in place of the floating point versions in the previous post, the two predicates become 

bool orient(
    const point_id i, const point_id j,
    const point_id k, const point_id l) 
{
    const auto [a2, b2, c2, d2, e2, f2] = quad_d2s(i, j, k, l);
    return exact_d2::orient(a2, b2, c2, d2, e2, f2) < 0.;
}

bool in_circle(
    const point_id i, const point_id j,
    const point_id k, const point_id l) 
{
    const auto [a2, b2, c2, d2, e2, f2] = quad_d2s(i, j, k, l);
    return exact_d2::in_circle(a2, b2, c2, d2, e2);
}

Limitations

Two assumptions are worth spelling out. First, these predicates are exact with respect to the squared distances you give them. If you compute the squared distances from floating point coordinates, they are rounded, and the predicate can't tell. That's the natural notion of exactness in a coordinate-free setting, since the distance matrix is the input, but it means the mesh you get is Delaunay with respect to the rounded metric, not the one you started with. Second, the error-free transformations fail if products underflow or sums overflow (subnormal inputs, for example, break two_product), so inputs need to stay within a reasonable exponent range, like Shewchuk's. The inputs also shouldn't be negative.

Finally, neither predicate checks that the six numbers are the squared distances of a real quadrilateral; for inputs that violate the triangle inequality the polynomials are still well defined and are computed exactly, but they don't mean anything.
